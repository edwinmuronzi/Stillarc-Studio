# Studio feature evaluation — 12 November 2026

Scope: current official publisher descriptions, compared with Studio 0.28 source and tests. This is not a competitor hands-on benchmark, verified popularity ranking, representative user survey or parity claim. Platform, region and paid tiers differ. No external beta or App Store preparation is part of this work.

## Recommendation

Keep Stillarc Studio as a complete photo editor and photo/video color-finishing app. Build a separate timeline-editing companion when the grading and batch workflows are strong. A photo editor deserves retouching, subject/background work and reliable batch sessions; it need not stop at color sliders. Multi-clip editing, titles, animation and audio need a different document model and navigation.

A separate app does not inherently use less power: workload, hardware decode, render scheduling, cache budgets and preview strategy determine energy. Sharing a tested rendering/color core avoids inconsistent results. Plan source-plus-recipe handoff so people do not have to export/recompress between apps; compatibility and media ownership must be explicit. The companion is a proposal, not an approved new project.

## Publisher precedents and actual Studio gaps

- [Lightroom mobile masks](https://helpx.adobe.com/lightroom/mobile/masks-and-selective-adjustments/create-masks.html), [batch settings](https://helpx.adobe.com/lightroom/mobile/share-save-and-export/copy-and-paste-edits-to-photos.html) and [HDR photos](https://helpx.adobe.com/lightroom/mobile/adjust-light-and-color/edit-hdr-photos.html): targeted editing, reusable edits and a deliberate HDR still workflow. Studio already has subject/sky/brush/range masks, four local layers, global color tools and selective batch paste. Gaps: first-class background selection/paired subject-background edits, richer local controls, swipe-through batch sessions, deeper RAW development and HDR still export.
- [PeekLUT](https://peeklut.app/) and its [publisher listing](https://apps.apple.com/us/app/color-grade-video-peeklut/id6473661560): LUT/technical transforms, film effects, batch grading and advanced export options. Studio already has .cube import/export, selected Log transforms, curves/wheels/mixer, grain/halation and HEVC HLG. Gaps worth evaluating: stronger shot matching, gamut/output management, color warping, more validated camera transforms, HaldCLUT and hardware-appropriate ProRes. DCTL and ProRes RAW are separate engineering/codec investigations, not quick checkbox additions.
- [Darkroom](https://darkroom.co/) and [local masks](https://darkroom.co/help/edit/masks-local-adjustments): a native library-first photo/video workflow, object/subject/background targeting and editable history. Studio should improve navigation between related images, source-specific local editing, preview memory bounds and discoverability. Do not copy spatial masks blindly between photos.
- [Photoroom background removal](https://www.photoroom.com/batch/background-remover): isolating foreground for transparent/replacement backgrounds. Studio currently edits a selection; it does not remove backgrounds. Add a separate cutout operation with hair/edge refinement, transparent PNG output and original preservation. Subject selection alone is not finished matting. Static photo cutouts should precede temporally stable video cutouts.
- [Lightroom healing](https://helpx.adobe.com/lightroom/mobile/heal-clone-and-remove/replace-areas-using-the-heal-tool.html): a clear missing photo workflow. Start with on-device spot heal/clone and dust/blemish cleanup. Generative replacement should remain optional future work with transparent network/privacy/power behavior, not a prerequisite for editing.
- [LumaFusion](https://luma-touch.com/luma-fusion-for-ios/) and [keyframing](https://luma-touch.com/speed-and-enhanced-keyframing/), [CapCut publisher listing](https://apps.apple.com/us/app/capcut-photo-video-editor/id1500855883), [VN publisher listing](https://apps.apple.com/us/app/vn-video-editor/id1343581380): timeline assembly, animated overlays and audio are a distinct workflow. A companion should cover precise cuts, ripple/roll edits, tracks, transforms, fades/transitions, titles/captions, sound/voiceover and keyframe easing before a large effects/template catalog.
- [DaVinci Resolve for iPad](https://apps.apple.com/us/app/davinci-resolve-for-ipad/id1581363826): useful inspiration for separation of editing and color tasks. Its tablet/codec/features should not be assumed to apply to every iPhone. Borrow clear workflow boundaries rather than exposing a desktop interface on a phone.

## Proposed Studio batches, in order

1. **Editing pool / sessions.** Select projects → Edit together. Keep a filmstrip and Previous/Next/swipe navigation, with a large preview. Clearly choose This item, Selected or Entire pool. Show a master grade and per-item overrides; support explicit sync of selected adjustment sections, reset individual overrides and recoverable before-sync versions. Pause hidden video, cancel stale loads, decode one active item and prefetch only a bounded neighbor. Save pool membership/order and per-project edits. Global grades can transfer across photo/video; Log interpretation, crop, masks, trim and HDR choice stay per source unless explicitly requested. Recreate adaptive masks per source, never copy the previous image's pixels. Swipes must not interfere with crop/mask gestures. Cover interrupted batch work and mixed-file failures.
2. **Subject and background.** One action creates separately named, editable selections with independent light/color controls. Add duplicate/invert and richer local adjustments, with edge inspection and manual refinement. Then implement background removal, transparent export, solid/image replacement and bounded blur. Preserve original and ensure premultiplied alpha, clean hair/edges and consistent color handling. Video removal requires temporally stable matting; current position tracking only translates a saved shape and is not equivalent.
3. **Finish photo development.** RAW white balance/decode controls, camera fixtures and highlight recovery; chromatic aberration/defringe and validated lens profiles; practical heal/clone; zoom/detail inspection; HDR still preview/export and an explicit SDR proof. Preserve reversible originals. Face/skin selections and advanced denoise follow only after quality and energy validation.
4. **Finish color workflows.** Reference-image and side-by-side shot matching, scopes, useful skin-tone guidance, flexible curves/color warping, clear input/working/output choices and validated camera transforms. Strong look organization and batch consistency matter more than a huge stock-filter list. Add keyframed grade/mask strength and better tracking correction only with sound timestamp/undo behavior. HDR output and codec choices need source/output fixtures and real-device capabilities.
5. **Interchange and resilience.** Portable source-plus-edit project packages, relinking, session backup/restore, export queue, output size/quality choices and optional professional codecs on supported hardware. No mandatory cloud or always-running background engine. Continue permissions, low-storage, cancellation, RAW/HDR and device checks.

## Proposed timeline companion, after a separate go-ahead

Keep an uncluttered media pool, a contextual inspector and four main task areas: Cut, Color, Sound and Titles/Effects. Editing first: assemble/reorder/split/trim clips, frame-accurate seeking, mixed orientations/frame rates and reliable audio sync. Then add overlays, eased transform/opacity keyframes, basic transitions, speed/reverse/ramping, chroma key, stabilization and position tracking. Sound needs level/fades, waveforms, voiceover, ducking and optional cleanup; captions need editable text/timing and accessible styles. License fonts and any sound/music catalog. Download optional effects/models only when needed.

Use proxy playback and render caching for complex sequences while exporting from originals. Handle only visible tracks/frames, bound decoders and memory, and pause inactive views. Give an honest preview-quality selector rather than reducing final export quality. Long multi-layer 4K/HDR rendering consumes power; promise measured limits and graceful thermal behavior, not zero heat.

## Immediate next implementation recommendation

The editing pool comes first, then paired subject/background controls. This directly addresses the user's stated workflow while building on tested project/copy-paste infrastructure. No timeline project or new advertised feature was implemented by this evaluation.


### Implementation status after this evaluation

0.29 implements the editing-pool workflow and paired Subject/Background controls described above. Sync explicitly writes selected adjustment sections to destination recipes with recovery versions; a live inherited master grade is not implemented. The source-specific masks/crop/input/clip settings stay individual. Background removal, replacement, video matting and the proposed timeline companion remain future work.


0.30 adds reversible photo cutouts, transparent PNG (including mixed batches), and grouped pool Undo/Redo. Subject/background selection still uses an estimated matte; it is not changing-pose video matting. Background replacement and the timeline companion remain future work. No beta or App Store work is included.


0.31 completes the scoped static-photo work in batches 2–3: replacement solid/image/original-blur backgrounds; duplicate/invert and richer local light/color/detail controls; supported native RAW decode/WB/recovery/lens/noise settings; manual chromatic/defringe; spot heal/clone; on-demand full-resolution detail tile; HDR still preview, SDR proof and 10-bit HLG HEIF delivery. Editing-pool delivery supports all or selected items. Camera-profile support is decoder-reported, not a claim of multi-camera calibration. Face/skin selections, advanced denoise and temporally stable video removal remain conditional future work. No timeline or beta/store work is included.


0.32 begins batch 4 with persistent private reference-image comparison, edited project snapshots, a bounded request-only statistical shot-match suggestion, reversible strength and portable matching corrections, plus an SDR vectorscope skin-hue guide. It is not semantic/object-aware matching or a universal skin-color target. Clearer color-warp controls, additional validated camera transforms, grade/mask keyframes and output/interchange work remain future checkpoints. Empty Bin is also added with snapshot confirmation and restore-aware deletion.


### 0.33 checkpoint
Color Warp adds up to four soft hue/richness controls in the fused GPU color pass, reversible direct-map and slider controls, Color-group sync, schema-5 presets and color-LUT export. Single/pool photo/video delivery adds remembered longest-edge size limits and compression choices, with full-source grading, alpha/HDR preservation and no upscaling. Video color-map editing uses the first kept frame; review playback in the editor. Advanced camera transforms, grade keyframes, portable project packages and an export queue remain later scope. No external beta/store preparation or timeline companion is included.


### 0.34 checkpoint
Portable .stillarc backups now package up to 20 projects with exact originals, source-specific edits/assets, LUTs, masks/tracking, organization and saved versions. Home offers labelled Home Backups button and single/selected-project entry points, separate Back up/Restore modes, persistent progress/cancel controls and safe new-copy restoration. Streaming integrity checks reject damaged/truncated/traversal/unsupported files before commit. Preset libraries, editing-pool membership, global preferences, cloud sync, an export queue, additional camera transforms and grade keyframes remain separate scope. No beta/store work or timeline companion is included.


### 0.35 checkpoint
Fixed backup asset paths across canonical/symlink directory aliases, with an aggregate-only read-only audit of actual device projects. The picker gains bounded photo/video thumbnails and fixed All/selected actions. Back up all writes complete numbered 20-project parts rather than omitting later projects. A persistent serial export queue snapshots per-delivery settings, supports explicit start, foreground pause/retry, ordering, retained completed files and safe removal, and is available from single/batch/pool delivery and Home. Queue work pauses while hidden or inactive; active unfinished work restarts at job boundaries. Additional camera transforms, grade keyframes, source relinking and Camera/Studio shared-look interchange remain separate scope.


### 0.36 checkpoint
Source-time video animation now covers exposure offsets and look/LUT/local-mask strength fades, with bounded points, Linear/Smooth interpolation, live slider preview, seek/add/update/delete/move, source/pool Undo/Redo and portrait/landscape layouts. Frame-time grading is shared by preview, direct/queued export, references and saved-source work. Animation stays out of reusable grades/LUTs; versions and backups retain it. New packages require reader build 40; queue schema 2 preserves animation while still loading earlier records. Additional camera transforms, source relinking, richer tracking correction and shared Camera/Studio look interchange remain separate scope.
